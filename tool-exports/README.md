# tool-exports

Automated exports of the **live annotation tool's** dataset — the current,
auto-refreshed source of truth for what the annotation team has produced. Written
daily by the `Sync annotations from the tool` GitHub Action
([`.github/workflows/sync-annotations.yml`](../.github/workflows/sync-annotations.yml)),
and refreshable on demand from the Actions tab.

## How to get the annotations

- **Everything in one file:** **[`annotations.csv`](annotations.csv)** — every
  annotation across all filings. GitHub renders it as a sortable, searchable
  table; use "Download raw file" to save the whole CSV.
- **One company / one year:** open **[`by-company/`](by-company/)** — an index of
  every company; pick a company, then a year, to open (and download) just that
  filing's annotations.
- **Only finalized results:** in any of the files, filter to rows where
  `adjudicated_status` is `agreed` or `resolved`. Note this keeps single-annotator
  filings (no second opinion) and filings whose adjudication is not yet marked
  complete; a filing-level "finalized" flag is planned.
- **What is in the file:** research data only. Screening filings and rows from
  admin, screening and demo accounts are left out, and `disputed` is computed
  among each filing's real annotators.
- **Per-filing summary:** **[`filings.csv`](filings.csv)** — one row per filing
  (annotators, statuses, sentence counts, tagged/agreed/disputed/resolved counts,
  finalized and archived state, and filings that had no AI content). Join to
  `annotations.csv` on `doc_id`.
- **[`MANIFEST.md`](MANIFEST.md)** — when it was last refreshed and how many rows.

Everything is regenerated by the job; don't edit these files by hand.

## Column guide

### annotations.csv

Each row is one annotation (multi-sentence tags are collapsed to a single row).

| Column | Meaning |
|---|---|
| `cik` | SEC Central Index Key of the company, zero-padded to 10 digits. |
| `company` | Company name as listed in the SEC index (often the upper-case legal name). |
| `year` | Filing year taken from the accession number. Can differ from the fiscal year for companies whose fiscal year does not end in December. |
| `accession` | SEC accession number of the 10-K filing. |
| `section_name` | The 10-K item the sentence is in (e.g. Item 1A - Risk Factors). 'Full Document' means the parser found no item headings in that filing. |
| `sentence_ordinal` | Position of the sentence within the filing's ingested sentences (all sections in order). A comma-separated list for a multi-sentence tag. |
| `sentence_text` | The sentence text. For a multi-sentence tag, the member sentences joined with a space. |
| `has_ai_keyword` | true/false — whether the sentence matched an AI keyword at ingestion. false rows are sentences the annotator tagged without a keyword hit (usually adjacent context). |
| `matched_keywords` | The AI keyword(s) that matched, '; '-joined. Union across member sentences for a multi-sentence tag. |
| `annotator_name` | The account that created this tag. |
| `kind` | Risk, Mitigation, or Responsible AI Commitment Statement. |
| `category` | Taxonomy category (e.g. Legal, Sociotechnical, Competitive). '-' for Commitment tags, which have no category. |
| `subcategory` | Taxonomy subcategory (e.g. Ongoing Litigation, Privacy & Security). '-' for Commitment tags and for AI Safety (General, Broad). Renamed labels (Litigation -> Ongoing Litigation, Compliance Costs -> Compliance costs/burdens) are migrated everywhere. |
| `strength` | Mitigation only: 1-3 per the strength rubric; blank for Risk and Commitment. |
| `note` | Free-text note the annotator attached to this tag. May contain line breaks. |
| `status` | The annotator's status on this filing (done / in_progress): at export time for live filings, frozen at archive time for archived ones. |
| `disputed` | SENTENCE-level. true if the filing's real annotators disagreed on this sentence: not every one of them tagged it, or their sets of (kind, category, subcategory) differ. Strength and note are ignored. Same value on every row of the sentence; a multi-sentence tag is true if any member sentence is disputed. On a single-annotator filing it is true when a second person was assigned but tagged nothing. |
| `pair_disputed` | TAG-level. true if THIS exact (kind, category, subcategory) was not given by any other annotator on the sentence(s) this row covers. Rows on the same sentence can differ: a shared tag is false, an unmatched one is true. Always true on single-annotator filings. |
| `group_id` | Identifier of a multi-sentence tag; blank for single-sentence tags. Each id appears once because the group is collapsed into this row (sentence_ordinal lists the members). |
| `spans_n_sentences` | How many sentences this tag covers (1 unless a multi-sentence group). |
| `context_sentence_ordinals` | Ordinals of extra sentences the annotator attached as context (never overlapping the tagged sentences). |
| `context_sentence_text` | Text of those context sentences. |
| `adjudicated_status` | The sentence's post-adjudication verdict: resolved if a final decision exists for the sentence (wins even over agreed when an agreed sentence was edited in adjudication); else disputed; else agreed. Blank only on filings adjudicated outside the tool (Google Sheet) before this column existed. |
| `final_kind` | Kind of the FIRST final adjudicated tag. Blank when not resolved, or when the decision was 'no tag'. See final_tags for the complete set. |
| `final_category` | Category of the first final adjudicated tag. Same blank rules as final_kind. |
| `final_subcategory` | Subcategory of the first final adjudicated tag. Same blank rules as final_kind. |
| `final_strength` | Strength of the first final adjudicated tag (Mitigation only). Same blank rules. |
| `final_tags` | The COMPLETE adjudicated decision, '; '-joined (Kind · Category · Subcategory, plus · S1-S3 for Mitigations). Use this rather than the final_* columns when a sentence resolved to more than one tag. Blank plus resolved means resolved to NO tag. |
| `doc_id` | The tool's id for the filing. Joins to filings.csv. |
| `annotation_id` | The tool's id for this tag (one per row). Stable across exports; use it to de-duplicate. |
| `annotator_id` | The tool's id for the annotator account. |
| `resolved_to_none` | true when the sentence was adjudicated and the decision was NO tag (final_tags is blank on purpose). Blank when the row predates this column. |
| `resolved_by` | Name of whoever recorded the final decision (blank unless resolved). |
| `resolved_at` | When the final decision was recorded (UTC, blank unless resolved). |
| `n_comments` | Number of adjudication comments on this sentence (0 when there was no discussion). |
| `adjudication_comments` | The discussion thread: 'Name (timestamp): text' entries joined by ' \| '. Internal; contains names. |
| `strength_disputed` | Mitigation only. true when the other annotator gave the same tag but a different strength (the agreement check ignores strength, so such rows still count as agreed). |
| `filing_finalized` | true when adjudication for the whole filing was marked complete (the Done button, or a legacy Google-Sheet adjudication). Same value on every row of the filing. |
| `adjudication_done_at` | When the filing's adjudication was marked complete (UTC; blank if not yet). |
| `archived` | true when the filing has been archived (its rows come from the archive snapshot). |

### filings.csv

One row per filing, including filings that had no AI content.

| Column | Meaning |
|---|---|
| `doc_id` | The tool's id for the filing (blank for no-AI filings, which never became a filing). |
| `cik` | SEC Central Index Key, zero-padded to 10 digits. |
| `company` | Company name. |
| `year` | Filing year (from the accession number). |
| `accession` | SEC accession number. |
| `no_ai_content` | true for a (cik, year) that was fetched and had no AI-relevant sentences, so there was nothing to annotate. Such rows have no annotators or counts. |
| `is_screening` | true for a screening/calibration filing (only present when explicitly requested). |
| `archived` | true when the filing has been archived. |
| `n_sentences` | Number of sentences ingested for the filing (blank for filings archived before this was recorded). |
| `n_keyword_sentences` | How many of those sentences matched an AI keyword. |
| `annotators` | The filing's real annotators, '; '-joined. |
| `annotator_statuses` | Each annotator's status (done / in_progress / not_started), as 'Name=status; ...'. |
| `annotator_done_at` | When each annotator marked the filing done (UTC), as 'Name=timestamp; ...'. |
| `n_expected_annotators` | How many annotators were supposed to work the filing (from the admin assignments). |
| `filing_finalized` | true when adjudication was marked complete (Done button or legacy Google Sheet). |
| `adjudication_done_at` | When adjudication was marked complete (UTC). |
| `legacy_sheet_url` | Google Sheet URL for filings adjudicated outside the tool (older filings only). |
| `n_tagged_sentences` | Distinct sentences with at least one tag from a real annotator. |
| `n_agreed` | Tagged sentences where the annotators agreed (no adjudication needed). |
| `n_disputed_open` | Tagged sentences still waiting on adjudication. |
| `n_resolved` | Tagged sentences with a recorded final decision. |
| `n_resolved_to_none` | Of the resolved sentences, how many were resolved to no tag. |
| `n_comments` | Total adjudication comments on the filing. |

## How it works (read-only, isolated)

The job logs into the live tool as a dedicated read-only service account
(`export-bot`) and downloads `/export.csv` — the same "Download all" the admin
page offers — plus `/export-filings.csv`. All the query work happens inside the app, next to the database, so
it finishes in under a minute. Splitting into `by-company/` is pure local
processing on that downloaded file. The job never modifies the tool, the tool's
database, or anything in this repo outside this folder, and it only commits when
the data actually changed.
